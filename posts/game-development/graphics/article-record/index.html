基于物理着色：BRDF

金属，塑料，傻傻分不清楚

有了上一节的信息，直觉告诉我们一个想法，对于导体和绝缘体

，应该分开用不同的保存方法。导体存specular颜色，因为它的diffuse是0。绝缘体存diffuse，因为specular非常弱，都用0.04这个常量表达就可以了。那么半导体呢？就需要一个“金属性”的系数，在两者之间插值。

用公式来表达，就是

diffuse = albedo * (1 - metalness) specular = lerp(0.04, albedo, metalness)

其中，albedo就是3通道的反照率，metalness就是金属性系数。lerp是线性插值

的意思。这样就用一个方法统一了导体、半导体、绝缘体的颜色分布。metalness = 0表示绝缘体，diffuse就是albedo，specualr = 0.04。metalness = 1表示导体，diffuse = 0，specular = albedo。这么一来，只要在GBuffer里面存albedo（3通道）和metalness（1通道）。

15 Vulkan

  • No Graphics API

    文章核心观点

    现有的“现代”图形API（如DirectX 12、Vulkan、Metal）已经过时且过于复杂。它们的设计基于10多年前的硬件架构，而当今的GPU已经发生了根本性进化。因此，我们需要一个全新的、极简的、完全“无绑定”（bindless）的图形API设计，其核心理念是：用单一的64位GPU指针和一个全局可访问的描述符堆来替代现有API中复杂的资源绑定、状态管理和管线对象（PSO）。

    详细原因与论证

    作者从历史、技术和实践三个层面，系统地论证了为什么需要一场彻底的变革。

    1. 历史原因：API是为“古代”硬件设计的妥协产物

    硬件差异巨大：早期的GPU（如3dfx Voodoo 2）拥有分离的内存和固定的功能单元，与现代GPU的统一计算架构完全不同。为了兼容这些多样化的硬件，OpenGL和DirectX等API不得不做出大量妥协。

    驱动承担了过多工作：旧的API（如OpenGL、DirectX 11）是“即时模式”，允许开发者细粒度地设置状态。为了适配底层硬件，驱动层不得不进行大量的映射、验证和重排工作，这增加了复杂性并降低了效率。

    “现代”API的诞生背景：DirectX 12、Vulkan和Metal（被称为“现代API”）是为了解决旧API的效率问题而诞生的。它们引入了“持久化对象”（如PSO、描述符集），将复杂的状态组合和验证工作提前到创建阶段，以减少运行时的开销。然而，这个设计主要是为了适应当时（约10年前）GPU的局限性，例如缺乏统一的缓存层级和高效的原始内存加载路径。

    2. 技术原因：当今GPU已经进化，但API却停滞不前

    作者指出，过去十年GPU硬件发生了巨大的变化，使得现有API中的许多复杂机制变得多余：

    统一的内存模型：

    • 现代GPU都拥有完整的、一致的末级缓存（LLC）。

    • PCIe Resizable BAR（可调整大小基地址寄存器）和UMA（统一内存访问）让CPU可以直接读写GPU显存，无需通过缓慢的上传缓冲。

    • 结论：不再需要复杂的堆管理（heap management）和上传/回读（upload/readback）API。gpuMalloc这样的简单函数就足够了。

    原生的64位指针支持：

    • 现代GPU原生支持64位指针，着色器可以直接解引用GPU内存地址。

    • 结论：不再需要各种抽象的缓冲区类型（常量缓冲、结构化缓冲、字节地址缓冲等）和对应的视图（CBV/SRV/UAV）。一个const MyData* data指针就能完成所有数据输入。

    无绑定（Bindless）纹理采样：

    • 现代GPU支持通过32位索引在一个全局的描述符堆（Descriptor Heap）中访问任意纹理，无需在绘制调用前预先绑定。

    • 结论：消除了繁琐的根签名（Root Signature）、描述符表（Descriptor Table）和绑定API。只需在着色器中声明一个 Texture textureHeap[]即可。

    可编程顶点拾取（Programmable Vertex Fetch）：

    • 现代GPU的顶点着色器可以直接执行原始内存加载指令来获取顶点数据，固定功能的顶点拾取硬件已成为过去。

    • 结论：不再需要输入布局（Input Layout）描述和顶点缓冲区绑定API。顶点数据就是一个普通的GPU指针，开发者可以用任何方式组织它。

    3. 实践原因：现有API带来了严重的开发和使用问题

    管线状态对象（PSO）爆炸：这是作者认为最大的问题。由于PSO包含了几乎所有渲染状态（顶点布局、光栅化状态、混合模式、深度模板状态等），任何状态的微小不同都需要创建一个新的PSO。这导致：

    • 游戏加载时间极长，玩家本地PSO缓存可能超过100GB。

    • 游戏过程中出现严重卡顿（stutter）。

    • 开发者需要维护庞大的离线编译系统和云端PSO缓存。

    屏障（Barrier）过于复杂：现有API要求开发者精确跟踪每个资源的生命周期和状态转换（如从渲染目标到着色器资源）。作者指出，现代GPU硬件实际上并不关心单个资源的状态，它们只需要知道执行阶段的依赖关系。当前的屏障API浪费了大量CPU时间来构建驱动最终会丢弃的资源列表。

    着色语言落后：HLSL和GLSL仍然缺乏对指针的原生支持，导致数组处理困难，无法编写可复用的库函数，阻碍了着色器生态系统的建立。相比之下，CUDA的指针语义使其拥有了丰富的库生态。

    作者的解决方案：一个极简的“新API”

    作者提出了一种新的API设计思路，其核心特征如下：

    内存管理：类似CUDA的gpuMalloc/gpuFree，返回可直接被CPU写入和GPU读取的指针。

    数据传递：所有着色器的输入都是一个单一的、只读的64位GPU指针，指向一个由用户定义的C结构体。结构体内可以包含其他GPU指针、32位纹理索引等。

    纹理访问：全局的、可索引的纹理描述符堆，通过32位索引访问。描述符可以由CPU或GPU直接写入。

    管线状态：大幅简化PSO。移除顶点布局、大部分光栅化状态。深度模板和混合状态作为独立对象，可以动态设置，从而减少PSO数量。

    屏障：简化为只有阶段掩码（生产者阶段 -> 消费者阶段）和少量特殊标志（如无效化描述符缓存），不再需要资源列表。

    总结

    这篇文章的核心思想是：我们不应该再被10年前的技术限制所束缚。 当今的GPU硬件已经足够强大和统一，足以支持一个更简单、更直接的编程模型。作者呼吁业界（特别是Khronos Group和Microsoft）在下一代API（如Vulkan 2.0或DirectX 13）中进行一次“干净的切割”，彻底拥抱无绑定、指针化的设计，从而从根本上解决当前图形开发的复杂性和性能瓶颈问题。文章核心观点

    现有的“现代”图形API（如DirectX 12、Vulkan、Metal）已经过时且过于复杂。它们的设计基于10多年前的硬件架构，而当今的GPU已经发生了根本性进化。因此，我们需要一个全新的、极简的、完全“无绑定”（bindless）的图形API设计，其核心理念是：用单一的64位GPU指针和一个全局可访问的描述符堆来替代现有API中复杂的资源绑定、状态管理和管线对象（PSO）。

    详细原因与论证

    作者从历史、技术和实践三个层面，系统地论证了为什么需要一场彻底的变革。

    1. 历史原因：API是为“古代”硬件设计的妥协产物

    • 硬件差异巨大：早期的GPU（如3dfx Voodoo 2）拥有分离的内存和固定的功能单元，与现代GPU的统一计算架构完全不同。为了兼容这些多样化的硬件，OpenGL和DirectX等API不得不做出大量妥协。
    • 驱动承担了过多工作：旧的API（如OpenGL、DirectX 11）是“即时模式”，允许开发者细粒度地设置状态。为了适配底层硬件，驱动层不得不进行大量的映射、验证和重排工作，这增加了复杂性并降低了效率。
    • “现代”API的诞生背景：DirectX 12、Vulkan和Metal（被称为“现代API”）是为了解决旧API的效率问题而诞生的。它们引入了“持久化对象”（如PSO、描述符集），将复杂的状态组合和验证工作提前到创建阶段，以减少运行时的开销。然而，这个设计主要是为了适应当时（约10年前）GPU的局限性，例如缺乏统一的缓存层级和高效的原始内存加载路径。

    2. 技术原因：当今GPU已经进化，但API却停滞不前

    作者指出，过去十年GPU硬件发生了巨大的变化，使得现有API中的许多复杂机制变得多余：

    • 统一的内存模型：
    • 现代GPU都拥有完整的、一致的末级缓存（LLC）。
    • PCIe Resizable BAR（可调整大小基地址寄存器）和UMA（统一内存访问）让CPU可以直接读写GPU显存，无需通过缓慢的上传缓冲。
    • 结论：不再需要复杂的堆管理（heap management）和上传/回读（upload/readback）API。gpuMalloc这样的简单函数就足够了。
    • 原生的64位指针支持：
    • 现代GPU原生支持64位指针，着色器可以直接解引用GPU内存地址。
    • 结论：不再需要各种抽象的缓冲区类型（常量缓冲、结构化缓冲、字节地址缓冲等）和对应的视图（CBV/SRV/UAV）。一个const MyData* data指针就能完成所有数据输入。

Ampere GA102, GA100 2020年 8nm / 7nm 第二代RT Core，第三代Tensor Core，支持PCIe 4.0。GA100计算卡采用7nm工艺和HBM2e。
Hopper GH100 2022年 4nm (TSMC N4) 面向超大规模AI/HPC，引入Transformer引擎、动态编程指令、第四代NVLink和HBM3。
Blackwell GB100, GB200 2024年 定制4NP工艺 新一代AI计算平台，采用芯片到芯片超高速互联，集成第二代Transformer引擎，性能大幅提升。
